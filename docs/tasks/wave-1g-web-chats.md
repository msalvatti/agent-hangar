## Rules of this lane

1. **Ordering is part of the contract.** Task 1G.1 (`src/shared/transcript` data layer + `use-api-query`) is the **first commit** on the branch and Task 1G.2 (transcript components + `shared/feedback`) the second — both before any `features/**` code — so W1-H can copy or stub against stable export names (plan §6 coordination note). The orchestrator merges W1-G before W1-H's final rebase.
2. **Architecture.** `features/<feature>/{components,hooks,services,lib}` with an `index.ts` barrel exporting only the public API; pages import from barrels. No import from another `features/*` folder. Shared modules (`@/shared/transcript`, `@/shared/repo-picker`, `@/shared/feedback`, `@/shared/shell`, `@/shared/api`, `@/shared/ui`, `@/shared/lib`) never import from `features/**` or from each other's internals (barrels only). `@agent-hangar/core` contract imports are fine everywhere.
3. **Pages are server components** (metadata, params) that render one client feature component; **all data fetching is client-side** through feature hooks built on `apiFetch`/`createEventSource` so the MSW browser worker intercepts everything in dev. Client components only where interactive (`'use client'` at the leaf that needs it).
4. **Mocks.** MSW is active when `NEXT_PUBLIC_API_MOCK=1` (dev, browser worker) and always in Vitest (node server). Handlers implement the `api/contracts` schemas exactly (responses are `parse`d by `apiFetch`, so a wrong mock fails tests). `src/mocks/handlers.ts` composes per-domain arrays and carries a marked line where W1-H appends `scheduledHandlers`/`settingsHandlers` (the only cross-lane edit, one additive line, resolved by the orchestrator).
5. **No new dependencies** (plan §3). Markdown: `react-markdown` + `remark-gfm` + `rehype-highlight`; palette: `cmdk` via the shadcn `Command`; toasts: `sonner`; everything else is stdlib/React.
6. **Coverage.** Extend `apps/web/vitest.config.ts` `coverage.include` with every owned `src/**` path (thresholds stay 100×4; `src/shared/ui/**` stays excluded as generated code). Page files under `app/**` are excluded from coverage (they are 5-line server wrappers) — keep them trivially thin.
7. **Secrets in tests** use canaries from `@agent-hangar/core/testing` (`GITHUB_CANARY`, `OPENAI_CANARY`); never a real-looking value. The transcript defensively masks secret shapes (`SECRET_SHAPE_PATTERNS` from core) before rendering.
8. **Contract changes** are never made here. If the UI needs a route the contract lacks, build the component behind a prop, wire it only if `routes` exposes the route, and report it in `contractChangeRequests` of the close-out return. (Chat rename IS in the contract: `PATCH /api/chats/:id`.)
9. Commit messages: Conventional Commits, English, no attribution trailers. One PR at the end (1G.7).

2. `reducer.ts` — `transcriptReducer(state, action): TranscriptState` (pure, immutable updates, no Date.now — `now` comes in the action). Mapping of `action.type === 'event'`:
   - dedupe: if `action.id` and `compareStreamIds(action.id, state.lastEventId) <= 0` → return state unchanged (export `compareStreamIds(a, b)` parsing Redis ids `ms-seq` numerically, falling back to string compare); otherwise set `lastEventId`, `lastActivityAt = now`.
   - `turn.started` → phase `preparing`, `startedAt = Date.parse(at)`.
   - `prepare.progress` → upsert notice with id `PREPARE_NOTICE_ID`, tone `info`, text = message (one line that updates in place).

   - `step.started` → `step`.
   - `assistant.delta` → append to the last item if it is an assistant item with `streaming: true`, else push a new assistant item (`id = 'assistant-<step>-<n>'`, deterministic counter from items length) with `streaming: true`; phase stays/becomes `running`.

   - `tool.call` → push tool item `status: 'running'`, `startedAt = now`, `stdout/stderr = ''`, `shownBytes 0`, `totalBytes null`; also finalize any streaming assistant item first (text as-is).
